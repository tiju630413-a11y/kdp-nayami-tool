# 構築時の判断記録（logs/decisions.md）

仕様にない細部を独自判断で決めた箇所と、その理由。
以降の運用・引き継ぎ（Opus 4.8）はこのファイルを前提にしてよい。

---

## Phase 1（2026-07-04）

### D-01: genre_map は 330 エントリ・カテゴリ別ID帯で生成
仕様の 300〜500 に対し 330（10カテゴリ × 32〜34件）とした。
初期資産としては検索性と網羅のバランス点であり、運用中に retro・トレンド観測から
追記して 500 へ育てる前提。IDはカテゴリ別に100番台で帯を分けた
（職場=W-0001〜, 人間関係=W-0101〜, …ライフイベント=W-0901〜）。
帯分けにより追記時のID衝突を防ぎ、IDだけでカテゴリが分かる。

### D-02: adjacent_ids は同一カテゴリ内に限定（初期版）
横断リンク（例: 職場の悩み ↔ メンタルの反芻思考）は価値があるが、
生成時に存在しないIDへの参照が混入するリスクを優先して排除した。
validate_genre_map.py が参照整合を検査するので、横断リンクは運用中に
安全に追記できる。

### D-03: validate_genre_map.py を scripts/ に追加（仕様のスクリプト一覧外）
仕様 §4.1 の「自己検証パス」を一回きりの手作業でなく再実行可能な
スクリプトにした。エントリ追記のたびに同じ基準で検証できる。

### D-04: スクリプトは標準ライブラリのみで動作、外部ライブラリはあれば使う
構築環境に PyYAML / Pillow が無かった（pip で導入は可能だが、運用者の
ローカル環境を仮定しない）。settings.yaml は簡易パーサで読み、
build_epub.py の画像圧縮は Pillow があれば実行・なければ WARN を出して
無圧縮で続行する設計とする。

### D-05: style_check の閾値は settings.yaml に外出し
読点間隔は目安9〜11字に対し WARN 帯を 7〜14 字とした（文体の個性を
機械で潰さないため、目安からの逸脱は FAIL でなく WARN）。
FAIL になるのは: 字数不足 / 文末3連続 / NG表現 / 具体性不足 / 診断的表現。

### D-06: PR は1本を貫通で使う
仕様・依頼文は「各Phase完了時にPRを作成」だが、作業ブランチは
`claude/kdp-nayami-tool-build-mpbyqr` 1本のみが許可されているため、
Phase 1 完了時にPRを1本作成し、Phase 2 / 3 は同じPRにコミットを積んで
Phase完了ごとに報告コメントを付ける方式とした。

### D-07: ng_phrases.txt は「検出＝再考」リストとして運用
「また、同様に」「一方で、」など、文脈によっては自然な語も含めた。
機械的に全削除するのではなく、検出箇所は review_loop の文体番人が
必要性を判定する（本当に必要な箇所は残してよいが、その場合も
連発は不可）。ただし出版ゲートの style_check では FAIL 扱いなので、
残す判断をした場合はリストから外すか表現を変える。

### D-08: 競合観測は CSV 1ファイル・週15分の軽量運用
仕様は「手動入力、CSV/JSON」のみ指定。列設計は plan の採点軸
「競合の薄さ」に直結する最小構成（件数・トップ本・AI氾濫度・勝ち筋メモ）にした。

### D-09: trend_topics.json に expires と昇格ルールを追加
時事の入口が恒常化した場合（例: リモートワーク）、genre_map 側へ昇格して
トレンドから外す運用を schema に明記。evergreen 資産を汚さないための弁。

## Phase 2（2026-07-04）

### D-10: pipeline.py は「状態管理＋プロンプト組立＋ゲート判定」に限定
モデル呼び出しは Claude Code / 任意のエージェントが行う前提のため、
pipeline.py は API を叩かない。各工程で「このプロンプトをこの文脈で実行せよ」
という実行指示書（books/NNN/_work/next_step.md）を生成し、成果物の存在と
品質ゲートを検査して次工程を解放する。これによりモデル差し替え・
枠切れ引き継ぎ（Fable→Opus）が「同じコマンドを叩くだけ」になる。

### D-11: review_loop の観点別コンテキスト分離は「観点別指示書ファイル」で実装
pipeline.py が観点ごとに独立した指示書（reviews/round{N}/{観点}_task.md）を
生成し、それぞれを**新しいコンテキスト（別セッション/サブエージェント）**で
実行する運用にした。API 直叩きをしないツール構成でも分離が担保される。

### D-12: performance.db のスキーマは books / sales / reviews / retro_weekly の4表
import_kdp.py は KDP レポート（販売・KENP の CSV）の列名ゆらぎに備えて
列名マッピングを引数で上書き可能にした。

### D-13: EPUB は EPUB3・縦書きなし（リフロー横書き）で生成
悩み系実用書は横書きが主流のため初期値は横書き。縦書き対応は
build_epub.py の設定（writing_mode）で将来切替可能な構造だけ用意。

## Phase 3（2026-07-05）

### D-14: 基準1号本は「draft直前」で意図的に停止
著者資産（assets.json）が0件のため、企画は W-0001（資産が最も厚く
集まる見込みの既存原稿テーマ）で確定しつつ、draft には入れなかった。
理由: 資産の捏造は差別化設計（§4.6a「どのAIにも出せない唯一の原材料」・
権利面の実質）を根本から毀損する。plan の資産割当欄・outline の資産ID欄を
「intake後に記入」と明示し、ゲート（項目4）が未割当のまま出版に進むことを
機械的に防ぐ。baseline.md は素の別コンテキストで実生成済みのため、
intake（30分）→ 割当（10分）→ 即 draft 着手が可能な状態。

### D-15: baseline はサブエージェント（プロジェクト非参照・ツール不使用）で生成
仕様 §5-4 の「素のプロンプト・履歴なしの別コンテキスト」を、ファイル参照を
一切させないサブエージェント実行で満たした。運用時も同じ方法を README の
定型指示から利用できる。

### D-16: タイトル・シリーズ名の確定（2026-07-05 著者回答反映）
タイトルは著者指定の『職場の理不尽から自分を守る台本36』を採用し、
サブに断言と命名FW（言い返せなくていい。「守りの一言」だけ持っていく）を配置。
シリーズ名は「作者名を入れない・直感的」の希望に基づき **「今夜の処方箋」** と
決定（深夜に検索する読者像に直結し、悩みカテゴリ横断で使える。
表紙のシリーズ帯は「今夜の処方箋 01」表記）。

### D-17: 著者資産は既刊合本版からの抽出で初期投入（24件）
著者提供の既刊『言い返せないあなたへ【合本版】』から、体験・観察・台詞・
失敗談・持論24件を構造化して assets.json に投入した。これは著者本人の
創作物からの抽出であり捏造ではない。draft ではコピペせず場面として
書き直す（03_draft の規則）。既刊は「参考」であり、本書（台本集）は
既刊（原理の教科書）と重複しない棲み分けを plan.md に明記した。

### D-18: モデル互換性の担保を仕様に明文化（§11追補）
運用者の求めにより「Fable 5以外での品質担保」を仕様§11として追記。
担保の実体は (1)判定基準の外部ファイル化 (2)不変の品質ゲート
(3)baselineの毎冊実生成 (4)還流の蓄積。基準値として基準1号本の
収束曲線（18→5→1・3周）を記録し、retroで比較する運用とした。

### D-19: 発信アカウントの外部化（§12追補）
note・Xは新設予定のため、URL・IDの出所を settings.yaml と book.json に
一本化。note_url が空なら build_epub が巻末のnote導線を自動省略する。
現行001のEPUBは既存アカウント（marvelous1101）入り——新IDが決まり次第、
設定を差し替えて再ビルドする。

### D-20: 新規デビュー作方針への転換（2026-07-05 著者指示）
既存アカウント（marvelous1101）と前著『言い返せないあなたへ【合本版】』への
言及を、本文・巻末・紹介文・note記事から全て除去。「儀式」「反撃のコスパ3問」
「最悪の三手」は既刊由来の表記をやめ、本書オリジナルの命名として再定義した
（命名FWの所有権が本書に立ち、差別化がむしろ強化される）。次に読む1冊は
シリーズ予告1行に自動フォールバック（build_epub）。既刊はあくまで
著者資産の原材料（内部データ）としてのみ利用を続ける。

### D-21: 目次ページの組み込み（2026-07-05 著者指示）
可視の目次ページ（toc.xhtml）を表紙直後のspineに追加。全9章＋台本36本へ
アンカーでジャンプ可能（リーダーメニュー用のnavも同じ入れ子構造に強化）。
台本集は拾い読みが主用途のため、小見出しは台本（D01〜D36）のみ載せ、
節見出しは載せない（目次の一覧性を守る）。以後の全冊に自動適用。
