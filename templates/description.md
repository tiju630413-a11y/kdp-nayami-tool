# Amazon 紹介文の型（templates/description.md）

promo 工程がこの型で生成する。**折りたたみ前の冒頭3行に全力を置く**
（スマホでは3行しか見えない。ここで痛み→変化が伝わらなければ以降は読まれない）。

合格条件: 固有の武器が「数字と名前」で提示されていること。
一般論の要約に読める紹介文は不合格として書き直す（内容ハイライトに
「◯◯の大切さを解説」のような文があれば即書き直し）。

---

## 構造

### 1. 冒頭3行（痛みの言葉 → 読後の変化）

- 1行目: 読者の夜の言葉をそのまま置く（genre_map の pain を使う）
- 2行目: その状態への同伴（責めない・分かる側に立つ）
- 3行目: 読後の変化の約束（具体的に。「楽になる」ではなく行動レベル）

例:
> 会議で頭ごなしに否定されて、言い返せないまま夜まで引きずる。
> 気が弱いからだと、自分を責めてきたかもしれません。違います。
> 本書を閉じるとき、あなたは「自分を守る最初の一言」を手にしています。

### 2. 内容ハイライト（固有の武器を数字と名前で）

必ず入れる要素:
- **実行装置の実数**: 「そのまま口に出せる台本38本」「7日間プログラム」など
- **命名フレームワークの名前**: 「本書が提案する『◯◯◯』という考え方」
- **当事者性**: 「研修現場で200人と向き合ってきた著者が」「当事者としての記録」
- 章立てのハイライト3〜5行（各行、読者の得るものベースで書く）

### 3. こんな人へ（3〜5項目）

genre_map の pain・reader から具体的に。「人間関係に悩む人」は禁止。
「日曜の夜、月曜の朝礼を思い出して眠れなくなる人」の粒度で。

### 4. シリーズ導線（既刊がある場合）

「◯◯シリーズ第◯弾。既刊『△△』とあわせてどうぞ。」1〜2行。

## NG チェック

- [ ] 冒頭3行だけ読んで「誰の・何が・どう変わる」が分かるか
- [ ] 数字が1つ以上入っているか（台本◯本・◯日間・ケース◯本）
- [ ] 命名フレームワークの名前が入っているか
- [ ] 「解説します」「〜の方法をご紹介」等の記事型言い回しがないか
- [ ] 本文に存在しない約束をしていないか（review_checklist 3-2）
